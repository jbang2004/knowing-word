# 识字讲解 v3 内容制度

v3 以人工旧版的自然讲解为风格标杆，但不照抄旧稿中的可疑字源。它把内容拆成两层：423 张“字事实卡”和 430 条“课文语境讲稿”。同一个字在不同课文、不同词语中可以复用事实，但必须分别落回本课语境。

## 内容边界

- 事实卡只保存可复用事实：儿童义、结构、主要部件、可说出的部件名称、证据等级和风险。
- 讲稿负责课堂表达：从本课词语或画面进入，带孩子看字形，解释本课词义，再回到课文作用。
- 记忆画面就是记忆画面。证据不足时，不说“本义、象形、会意、形旁、声旁”等字源结论。
- 生成器可以整理上下文、校验覆盖、制作索引与音频，但不拥有讲稿文字。

## 审核状态

`draft → reviewed → approved`。作者和复核者不能是同一角色；运行时与配音脚本只能读取 `approved` 内容。子 agent 只向 `artifacts/narration-v3/` 交草稿，主审逐条晋级，不能直接改批准库。

全书批准还需要 `artifacts/narration-v3/root-review.json`。它必须逐条给出 root 主审结论、硬伤标记和总分；只有 430 条全部无硬伤且达到 90 分，`npm run compile:narration-v3` 才会写入 `approved/book.json`。事实卡要先由人工复核为 `reviewed`，编译时才由 root 一并批准。

三包讲稿采用轮换交叉审稿，1–7 课由 QA 复核，8–16 课由内容编辑复核，17–26 课由技术编辑复核。`npm run validate:narration-review` 检查五维分、总分、硬伤和覆盖；三份报告全部通过后，root 才能运行 `npm run prepare:narration-root-review` 签署全书结论。

正式克隆音频固定使用 Qwen3-TTS 1.7B Base 4bit、批准的模型 revision 和“封”的固定参考音，0.6B、旧 revision 与旧 bf16 产物都不能进入正式母版。音频按“讲稿、参考音摘要、模型、模型 revision、随机种子、生成策略版本”计算内容哈希；当前 v3 策略还固定使用 bitexact WebM 封装，保证相同原始音频得到相同发布字节。随机种子从内容哈希派生，不受批次顺序影响。同文案、同权重、同策略才可稳定复用，任一项改动都生成新资源。ASR 回听只是机器门槛，特殊读音和最终成品仍须人工听审。批准库、音频母版和线上发布是三个独立步骤，编译批准内容不会自动切换运行时，也不会部署。

本地运行时先激活仓库 `.venv`，或把 `QWEN3_TTS_PYTHON` 指向装有 `mlx-audio` 的解释器。正式生成命令需要显式传入批准库，例如 `npm run generate:narration-qwen3 -- --input app/data/narration-v3/approved/book.json`。

生成阶段写入的逐字时间只是临时估算。正式验收要运行 `npm run verify:narration-qwen3 -- --manifest <manifest> --write-aligned-marks`，用 Qwen3 ForcedAligner 0.6B 8bit 按最终 `ttsText` 和实际音频重算时间；未写入 `timing_source=qwen3-forced-aligner` 的 marks 不能进入发布包。

每条交叉复核必须保存 `draftDigest`。它覆盖字、教学词、讲稿、课文连接、字形锚点、事实声明和风险说明。校验器会把摘要与当前稿件逐条比对；复核后只要改过一个字，旧复核立即失效，必须重新冷读，避免“审的是旧稿，批准的是新稿”。

全量音频生成、ASR 回读、ForcedAligner 对齐和人耳听审完成后，运行 `npm run validate:narration-qwen3-release -- <approved-book.json> <qwen-manifest.json>`。发布门会重新核对430条内容摘要、参考音色、模型、ASR分数、实际音频摘要、逐字时间和人耳结论；任一项缺失或音频在验收后被替换，都不能晋级到运行时。

## 单条硬门槛

- 85–150 个字符，通常 4–6 句；确有必要才允许主审书面豁免。
- 必须读准本课词语和多音字，解释当课所用词义。
- 必须有可观察的字形抓手，但不要求把每一笔硬编成故事。
- 课文关联必须具体到人物、物件、动作、情绪或说明关系，不能只在结尾贴课名。
- 教学词不在正文时，要用词义或阅读方法自然转回本课，不能反复说“课文没有写”“这里只是认字”；事实边界写进 `risks`，不把审稿说明念给学生听。
- 不贬低性别、群体、身体差异，不用血腥或羞辱画面帮助记忆。
- 口播时不直接念罕见部件符号，统一使用 `component-speech.ts` 中的课堂名称。
- 展示稿含拉丁拼音或特殊符号、模型容易误读时，另写 `ttsText`。它只能替换读法，不能改动教学信息。

批准编译时会把展示稿中的声调拼音转换成中文声调说法，例如“读zhuàn”变成“读第四声”；无声调拼音不能自动转换，必须人工补 `ttsText`。正式生成器发现拉丁文字会直接拒绝，避免模型把拼音字母逐个念出。

## 主审评分（100）

- 事实与边界 30
- 儿童能听懂 20
- 人工口吻与节奏 20
- 课文关联 20
- TTS 可读性 10

90 分及以上且没有硬伤才可批准。机械套话、虚构字源、错读、多音字失去语境、课文关联空泛，任一项都直接退回。
